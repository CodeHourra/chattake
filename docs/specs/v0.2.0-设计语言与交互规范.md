# 有得 v0.2.0 设计语言与交互规范

> 状态：实施基线  
> 方向：编辑感、克制的液态玻璃、Light/Dark 双主题

## 0. 品牌语言

- 中文名：**有得**；英文名：**ChatTake**。
- 产品全称：**有得 · AI 对话知识库**。
- 中文主张：**让每次 AI 对话，都有所得**。
- 英文主张：**ChatTake — Turn AI chats into reusable knowledge**。
- 品牌图形以“对话页 + 被保留的知识书签”为核心，不再使用足迹、放大镜或代码括号隐喻。

## 1. 设计原则

有得面向长期使用 AI 编程工具的个人开发者。界面应像安静、可信的研究档案，而不是高饱和的 AI 控制台。

1. 用线、留白和层级组织信息，不用满屏卡片。
2. 液态玻璃只用于顶栏、侧栏、浮层、任务中心和设置导航等结构层。
3. 朱砂只表示“值得注意”，松绿表示“稳定完成”；错误使用克制红色。
4. 动效解释状态变化，时长 120–220ms，无弹跳；尊重 `prefers-reduced-motion`。
5. 来源必须同时以 Logo、名称和文字状态表达，不能只靠颜色。

玻璃结构层统一使用 `backdrop-filter: blur(24px) saturate(106%)`；小型浮层可降为 18–20px。内容卡片不使用模糊。禁止彩色渐变、霓虹描边、厚重阴影和玻璃套玻璃。

控件高度固定为 32px（小）与 36px（常规），控件圆角 8px，面板圆角 12px。组件不得自行引入新的品牌色或圆角档位。

## 3. 字体与层级

- 中文界面正文使用平台清晰中文字体栈，标题使用宋体气质的衬线字体栈；代码和 ID 才使用等宽字体。
- 页面标题 20–24px，模块标题 15–17px，正文 13–15px，辅助信息 11–12px。
- 通过字号、字重和间距建立层级，不用大量彩色 Badge。

## 4. 核心布局

- 顶栏：产品切换、全局搜索、同步、设置、主题。
- 左侧：来源、项目、知识类型与标签筛选；Claude、Cursor、Codex、CodeBuddy 使用各自 Logo，OMP、Pi 使用清晰的单色来源标识。
- 主区：会话列表、知识库、草稿和详情路由。
- 进度中心：顶栏保留入口与微型进度，点击后以弹窗查看任务明细，不遮挡列表、正文或分页。

桌面端最小窗口宽度为 960px；960–1100px 时页头操作允许换行、列表次要元数据允许隐藏，主操作与任务状态不能隐藏。若未来支持低于 960px，侧栏再切换为可呼出的抽屉。

## 5. 任务与进度

同步阶段固定为“扫描来源 / 解析变化 / 写入会话 / 完成”；分析阶段固定为“准备内容 / 判断价值 / 提取知识 / 保存结果”。

进度必须来自后端真实计数，展示完成数、总数、当前来源或会话、供应商、模型、耗时和失败数。没有可靠总量时使用不定进度，不伪造百分比或 ETA。

取消当前分析会明确提示会终止本次模型请求；失败项可单独选择供应商后重试。

## 6. 知识与草稿

- 主类型只显示：决策、排错、实现、解释、片段。
- 主题标签和技术项分区展示；默认只显示高频项，完整列表渐进展开。
- 高价值知识自动进入知识库；中价值显示在“待审核”入口并带数量。
- 重新分析结果始终先成为草稿，发布时提供“替换旧知识 / 与旧知识并存”。
- 编辑状态必须提示未保存修改；人工编辑内容不会被后台分析静默覆盖。

## 7. 多供应商设置

设置页采用“配置列表 + 编辑区”，避免在一个表单内切换后覆盖密钥。API 与 CLI 是同级 Provider 类型；每套配置显示名称、类型、供应商或命令、模型、激活状态和最近测试结果。

模型控件可刷新远端列表，也可手填完整模型 ID。刷新失败不清空当前模型。测试连接若需发送最小模型请求，必须提前说明可能产生极少 Token。

CLI 配置展示命令路径与可选模型。“检测命令”只执行版本检查，不调用模型；运行参数由应用固定，避免用户参数覆盖只读沙箱和禁用工具等安全边界。

## 8. 无障碍与交互

- 所有交互元素有键盘焦点与可读名称，正文和控件满足 WCAG AA 对比度。
- 状态不能只靠红绿区分，必须有图标或文字。
- 加载不导致布局跳动；错误信息说明发生位置、原因分类和可执行的下一步。
- 品牌 Logo 使用官方提供资产，不改比例、不添加纹理和特效。
